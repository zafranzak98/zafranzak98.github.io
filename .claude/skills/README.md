# Project skills

Three skills copied unchanged from Emil Kowalski's skills repository
(https://github.com/emilkowalski/skills, commit 64eb3deb9a5f), under the MIT licence in
`LICENSE-emilkowalski-skills`. Only these three were taken; the repository's installer was not run.

| Skill | Used for | When |
| --- | --- | --- |
| `mobile-native` | Phone behaviour of the site and the visual editor: input zoom, tap and hover states, viewport height, safe areas | Before each release of the site or the editor |
| `break-ui` | Worst-case words in editable parts: very long words, empty parts, long titles | Before each release, and after adding an editable part |
| `review-animations` | A strict review of existing motion; it never adds motion | When motion changes |

The project's approved design requirements and documentation always take priority over these skills:
the Agreed requirements and Portfolio standards in the project documents, the colour palette, the
typography and the established art direction. Where a skill's advice conflicts with them, the
project's decision stands and the skill's advice is not applied.

To update a skill, copy the newer upstream file over it unchanged and note the commit here.
